# 07 · Agent 与确定性基线的对比评测

> 问题：**一个能规划、能调用工具的 Agent，能不能打败一个标定过的固定统计检验？**
>
> **最终结论（§9 之后）**：在这份任务上它**没有超过**标定基线，但它**追平了**——假阳性 8/25 → 1/25（p=0.023）、准确率不变、且它始终保持一项基线结构上做不到的能力（看见漂移与阶跃）。
>
> **差距不在模型，在信息。** 它的推理从头到尾都是对的；它缺的只是"这个数在正常时能到多大"。把这个事实做成工具，四倍的假阳性差距就消失了。
>
> ⚠️ **本文是有时间顺序的实验记录**：§1–§8 是第一次实验（Agent 假阳性 32%），§9 是补上零假设工具后的第二次实验，并**修正了 §7 的结论**。只想看结论的话直接读 §9.5。

---

## 1. 为什么要做这个对比

第 8 轮建立了一套受控故障注入评测，并记录了一个确定性基线：

```
Top-1 32.7%    Top-3 33.3%    检出 39.3%    假阳性 6.7%（目标 5%）
```

但那个基线**只是基线**。它存在的意义是被超越——而在它被超越之前，"Agent 比阈值法好"只是一句未经检验的话。这一轮把它检验了。

---

## 2. 方法：唯一公平的比法

**两边必须是同一批案例。** 比对不同案例集上的两个分数什么都证明不了，所以：

- 两个诊断器由**同一个 `run_suite`** 在**同一个 `build_cases` 输出**（同种子）上打分；
- 基线的阈值照 `baseline.json` 记录的方式标定（种子 7，400 个对照窗）。

**给 Agent 的信息，必须和基线一样多。** 这一点我第一版做错了，见 §5。

| | 确定性基线 | Agent |
|---|---|---|
| 输入 | 两个窗口的**全部数值** | 每个传感器的**中位数、标准差、极值、标准化偏移 `shift_se`、离散度比、离群点数**，以及一张全量的**同类相关性变化表** |
| 阈值 | 有，标定得来（45.0） | **没有** |
| 排序 | 无（它自己取最大值） | **没有** |
| 决策 | 一个固定统计量超过一个固定阈值 | 自己判断什么算异常 |

也就是说：**统计量相同，判断权归 Agent**。这正是要检验的命题。

**报告即终局。** 报告工具是终结性的——真实系统里调用它就已经开出工单了。这不是无关紧要的实现细节：允许反复报告会产生"以第一次为准还是最后一次为准"的歧义，而实测中确实有一个案例先正确诊断出卡死传感器、随后又两次撤回。

---

## 3. 结果（25 个注入故障 + 25 个健康对照，同种子）

```
                                baseline         agent
--------------------------------------------------------------------
cases                                 25            25
detected                               7            12
root cause Top-1                   16.0%         12.0%
root cause Top-3                   20.0%         12.0%
controls                              25            25
false positives                     8.0%         32.0%
```

| 故障类型 | 基线 Top-1 | Agent Top-1 | n |
|---|---|---|---|
| dead（卡死） | **100.0%** | 0.0% | 4 |
| drift（漂移） | 0.0% | **66.7%** | 3 |
| step（阶跃） | 0.0% | **33.3%** | 3 |
| spike（尖峰） | 0.0% | 0.0% | 8 |
| decorrelate（失相关） | 0.0% | 0.0% | 7 |

另有 **15/50（30%）的运行在 16 步内始终没有调用报告工具**，按"无故障"计。

---

## 4. 诚实的读法

**Top-1 16% 对 12% 不构成差异。** n=25 时，一个约 15% 的比率其 95% 置信区间大约是 ±14 个百分点。这 4 个百分点的差距没有任何统计意义，**我不认为 Agent 在 Top-1 上输了**。

**假阳性 8% 对 32%（2/25 对 8/25）是本次最强的信号**，但 Fisher 精确检验给出 p ≈ 0.07——**尚不足以称为定论**，只能说"看起来更差"。注意这个差距还是被低估的：30% 未完成的运行按"无故障"计，这**压低**了 Agent 的假阳性率，而它仍然是基线的四倍。

**唯一真正有意思的正向结果：Agent 检出了基线完全看不见的故障类型**——drift 2/3、step 1/3，而基线在这两类上都是 0/3。这正是第 6 轮点名的那类盲区。但是 **n=3，这只能算线索，不能算结论。**

**它反而漏掉了基线最擅长的那类**：dead 0/4 对基线 4/4。而调试中同一个 dead 案例它曾**正确报出传感器 209、组 26**。所以这不是能力问题，是**运行间的不稳定性**。

---

## 5. 它为什么误报：因为"大"不等于"异常"

Agent 的假阳性推理读起来**完全合理**，引用的数字也都是真的。例如：

> 传感器 203（组 25）呈现最清晰的故障特征：它与同组 7 个同类均值的相关性在参考窗为 +0.939，在待查窗塌缩到 −0.162（变化 1.101），是相关性表里最大的。同块内的邻近传感器也出现同样的断裂（206：+0.985 → −0.026，变化 1.011；197：变化 1.032……）

这段话没有任何事实错误。问题在于：**在一个健康窗口上，相关系数在 60 行与 200 行样本之间的波动，本来就可能有这么大**——而 Agent **没有零假设的概念**，所以它把"313 个传感器里最大的那个"当成了信号。

**这恰恰是标定过的阈值存在的理由。** 确定性基线在 400 个对照窗上测出零分布、把阈值放在 5% 分位点，处理的就是这件事。Agent 面对的是一个多重比较问题，而它用的是人类式的"这个看起来很大"。

我在 prompt 里明确警告过这一点（"三百多个传感器，看起来大的值可能只是最大的那个"），**它依然这么做了**。这本身是个有价值的观察：提示词层面的提醒，替代不了统计层面的校正。

## 6. 代价

| | 确定性基线 | Agent |
|---|---|---|
| 依赖 | numpy | 一个远程 LLM |
| 一次诊断 | 毫秒级 | ~33 秒、约 16 次模型调用 |
| 50 个案例 | < 1 秒 | **27.6 分钟** |
| 确定性 | 同输入必同输出 | **同输入可不同输出**（实测：同一 dead 案例一次报 209、一次报 46） |

## 7. 结论（**已被 §9 修正，先读 §9**）

> **如果你只读一节，读 §9。** 这一节给出的结论有一半在补上零假设工具之后不再成立：
> 「Agent 假阳性是基线的四倍」不是它的能力上限，而是我扣掉了它需要的一个事实。§9 记了
> 干预的做法、数字和逐项检验。本节保留原样，因为**被修正的过程本身是这份记录的一部分**。

**在这份任务上，一个标定过的固定统计量是更好的默认选择——更快、更稳、假阳性更低。** 它输掉的只有一类它结构上看不见的故障（漂移、阶跃、失相关）。

Agent 值得存在的地方不是"比阈值法更准"，而是：

1. **它能检出固定检验看不见的故障类型**（本次 drift 2/3、step 1/3，基线 0/3）；
2. **它的推理是可读的**——报告里带着具体数值和比较过程，工程师能据此判断该不该信；
3. **它不需要事先知道该看什么统计量**——基线的那一个统计量是人选定的。

而它要成为默认选择，差的正是第 5 节那件事：**它需要一个零假设的概念**。给 Agent 一个"在健康数据上这个统计量能到多大"的工具——也就是把标定过程本身变成一个可调用的工具——是这份对比指向的下一步。那才是"Agent 编排"真正该编排的东西。

---

## 8. 复现与边界

```powershell
# 需要 .env 里的真实 provider；用 fake 会被脚本拒绝，因为脚本化重放没有意义
uv run python -m eval.run_agent_eval --cases 25 --controls 25 --max-steps 16
```

**边界，逐条说明：**

- **样本小**：25 个故障，其中 dead 4、drift 3、step 3、spike 8、decorrelate 7。按类型的数字基本是轶事；
- **未完成按"无故障"计**：15/50 如此。这低估了检出率也低估了假阳性率；
- **`temperature=0` 并不保证跨运行确定性**，实测到同一案例的不同答案。因此单次运行的差异不应当作结论；
- **这是三轮运行的第三轮**。前两轮因我自己的缺陷作废：第一轮 prompt 声称"多数窗口是健康的"而实验中一半是故障（对 Agent 不公平）；第二轮丢了变量初始化，38/50 未跑完。这两轮的数字都没有被采用。

产物：[`eval/baselines/agent.json`](../eval/baselines/agent.json) 记录了本次运行的指标、按类型分解，以及每个案例它说了什么、为什么。

## 9. 干预：把标定变成 Agent 能调用的工具

第 7 节指向的下一步是「它需要一个零假设的概念」。这一节把它做出来并检验了。

### 9.1 干预内容

新增工具 `calibrate_null(statistic, iterations)`：Agent 可以指定一个统计量，工具**从这条产线的真实健康历史里采样相邻周期对**，回报该统计量在"什么都没坏"时的分布——分「单个传感器」和「313 个里最大的」两行。

**它不回报当前窗口落在分布的哪个位置。** 那等于直接把标定好的阈值交出去；Agent 拿到了尺子，自己量。这是被检验的部分。

### 9.2 一个必须记下来的弯路

第一版工具是**对当前案例自己的参考窗做自助重采样**。它错了，而且错在关键方向上：

| 统计量（最大 313 的 95 分位） | 自助重采样 | 真实相邻周期 |
|---|---|---|
| `shift_se` | 6.06 | **10.12** |
| `correlation_change` | 1.08 | **1.26** |

**原因**：同一周期内的行共享该周期的水平，自助法看不见「周期间」的移动——而那恰恰是真实零假设的主导成分。**过窄的零假设会让 Agent 报得更多，不是更少**，也就是朝错误方向推。

（我最初还把 45 误当成 `shift_se` 的零假设。45 是**基线阈值**，由 spike 规则（`40 + 离群点数`）主导，不是 `shift_se` 的分位数。这条更正一并记在这里。）

### 9.3 结果（同一批 50 个案例、同种子、同模型，只改工具可用性）

```
                   基线      无标定工具     有标定工具
根因 Top-1        16.0%        12.0%        12.0%
根因 Top-3        20.0%        12.0%        12.0%
假阳性             8.0%        32.0%         4.0%
16 步内未完成        —         15/50         3/50
```

| 故障类型 | 基线 Top-1 | 无工具 | 有工具 | n |
|---|---|---|---|---|
| dead | 100.0% | 0.0% | 25.0% | 4 |
| drift | 0.0% | 66.7% | 33.3% | 3 |
| step | 0.0% | 33.3% | 33.3% | 3 |
| spike | 0.0% | 0.0% | 0.0% | 8 |
| decorrelate | 0.0% | 0.0% | 0.0% | 7 |

**逐项检验**（Fisher 精确检验，双侧）：

| 对比 | p |
|---|---|
| **假阳性 8/25 → 1/25**（干预前后） | **0.023** |
| 未完成 15/50 → 3/50（干预前后） | **0.003** |
| 假阳性 1/25 对基线 2/25（干预后） | 1.00 |
| 假阳性 8/25 对基线 2/25（干预前） | 0.074 |

### 9.4 读法

**干预精确地作用在它该作用的地方，而且只作用在那里。**

- **假阳性降了四倍**（32% → 4%），这是同批案例上的配对比较，**p = 0.023**，统计上站得住。干预后 Agent 与标定基线在假阳性上**已经无法区分**（1/25 对 2/25，p = 1.00）；
- **它同时变得果断得多**：16 步内未完成的从 15/50 降到 3/50，**p = 0.003**。有了尺子就不再来回试探；
- **准确率一点没变**：Top-1 干预前后都是 12.0%。基线的 95% 置信区间 [6.4%, 34.7%] 与 Agent 的 [4.2%, 30.0%] 大幅重叠，**"谁更准"在这份样本上无法判定**；
- **它仍然是唯一能看见漂移和阶跃的那个**（各 1/3，基线 0/3），而 n=3 依然只是线索。

### 9.5 修正后的结论

第 7 节的结论要改一半。**"Agent 假阳性是基线的四倍"不再成立**——那是我给它的信息不完备造成的，不是它的能力上限。补上零假设之后，它与标定基线在假阳性上打平、在准确率上打平，而它多出的那项能力（看见固定检验结构上看不见的故障）依然在。

所以更准确的结论是：

> **在这份任务上，Agent 没有超过标定基线，但它追平了——而且它追平的方式说明了差距在哪：不在模型，在信息。** 它缺的从来不是推理能力（它的推理一直是对的，引用的数字也都是真的），而是"这个数在正常时能到多大"这一个事实。把这个事实做成工具，四倍的假阳性差距就消失了。

这也正是"Agent 编排"该编排的东西：**不是把更多判断交给模型，而是把模型无法自行获得的那些量，做成它能调用的工具。**

### 9.7 边界（在第 8 节之外补充）

- **干预前后的对比是配对比较**（同案例、同种子、同模型），所以 p = 0.023 和 0.003 是可解释的。**与基线的对比则只有 25 个案例**，不足以判定准确率高低；
- 按类型的数字 n=3～8，**仍然只能算线索**；
- 标定工具从**同一批 400 行历史**采样，而评测案例也从其中抽取。真实系统里标定数据应当更早、更独立；
- 工具允许 Agent 自己指定迭代次数，它每次都用了上限 500。
